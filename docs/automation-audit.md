# 自动任务逻辑审查与执行模式

审查日期：2026-09-15。以 `8803173` 后的工作区为基础，覆盖模块、本地执行库、云端调度、配置镜像与新增的 KSU 实验模式。本文区分「已经修复」与「仍有边界」，不把单元测试通过等同于后台长期运行已经验证。

## 1. 三种执行位置

| 执行位置 | 配置和凭据 | 谁实际访问阅微接口 | 如何唤醒 | 模块界面关闭后 |
| --- | --- | --- | --- | --- |
| Android 本地 | 模块私有存储；token 经 Android Keystore 加密 | 模块进程中的共用引擎 | 系统闹钟 → `LocalTaskJobService`；宿主前台镜像也可提交作业 | 能否及时运行仍受系统后台策略影响 |
| KSU 本地（实验性） | root 私有目录中的任务状态和 token 副本 | `app_process` 启动的独立进程；仍调用同一个 Kotlin 引擎 | KSU `service.sh` → 看门狗 → 到期执行 | 不依赖模块 Activity/应用进程存活，但仍依赖设备、脚本与网络 |
| 云端 | API 服务器保存任务与加密凭据 | Python 服务端执行器 | 服务端调度循环 | 云任务可继续；手机上的结果通知可能延迟 |

KSU 接管的是全部**本地任务**，不是替代云端服务器，也不是给每个任务另外复制一份配置。普通「Root 增强」只发唤醒广播，和 KSU 独立执行不是一回事。

## 2. 配置、调度与结果的完整链路

### Android 本地

1. 阅微里的设置页按阅微账号保存任务配置，token 用宿主自己的 Keystore 加密。
2. `LocalTaskMirror` 显式投递给模块；模块用自己的密钥重新加密 token。两个应用的 UID/Keystore 不通用，不能直接复制密文。
3. 配置按 `configUpdatedAt` 合并，执行进度由执行方维护；旧配置不能覆盖新的启用状态或新选项。
4. `CloudTaskWakeScheduler` 只在模块进程排闹钟。候选包括东八区零点、云任务预计完成点、本地任务到期点，以及 15 分钟兜底；过期时间安排短时重试，不拖到次日。
5. 闹钟接收器只重排和提交作业。网络请求不再留在 `BroadcastReceiver.goAsync()` 的生命周期内。
6. `LocalTaskRunner` 防重入；Android 模式调用 `LocalTaskEngine`，KSU 模式仅同步/排队，不再在应用里重复执行。
7. 共用引擎逐账号选择到期任务，每轮默认最多 8 个、每个任务最多执行一次；手动单任务允许对未启用任务执行一次，但不会把它重新启用。
8. 成功操作的关键阶段写检查点；最后合并运行状态、追加记录、排下一次时刻和投递结果通知。失败不能把已落盘的进度退回执行前。

普通失败默认 5 分钟重试；凭据缺失等 `paused` 结果在本地默认 1 小时后再试。HTTP/业务错误仍可能表现为普通失败，KSU 不会使失效 token 自动恢复。

### KSU 本地

1. 只有主 Android 用户可以开启；先确认配套模块已安装、未停用/待删除，并取得模块应用的 root 权限。
2. **先持久化 Android 不再执行的模式标记，再请求 KSU 接管**。即使命令超时、返回包丢失或应用在交接中退出，也不盲目恢复 Android，避免两端同时跑。
3. 通过 root 命令的标准输入传配置和 token，不把凭据拼到 shell 参数中。APK 仍须安装，KSU 脚本从当前 APK 加载执行器。
4. `/data/adb/reamicro-automation` 为 `0700`，凭据所在 `state.json` 为 `0600`。状态通过文件锁、临时文件、同步写入和原子替换保存；执行锁负责防止多个独立执行器同时跑任务。
5. 看门狗醒着时每 15 秒检查一次；按 `next-run-at` 执行，并在启动及每 15 分钟做一次保底核对，避免提示文件丢失后永远不执行。每轮执行有 240 秒超时，能保留已经写入的检查点。
6. 手动执行请求排队，不覆盖上一个尚未消费的请求；重排时间直接修改 KSU 的状态，不只改应用中的镜像。
7. 记录随同步回到应用；已清空的记录不会因为旧快照而重新出现。待发通知保存在 root 状态中，模块确认成功发出后才回执。
8. 切回 Android 时先停用 root 执行、等执行锁释放、清掉 root 凭据副本、导回最终进度，最后才恢复 Android 执行。命令超时仍需等任务结束后重试，不强行双跑。

实现入口：`KsuTaskBridge`、`KsuExecutionHandoff`、`KsuTaskMain`、`KsuTaskRepository` 和 `ksu/reamicro-automation/`。

### 云端

1. 任务 API 校验任务类型、凭据归属，配置请求加密存储。同账号、凭据和任务类型的重复配置复用已有任务。
2. 云端任务统一由服务器执行；历史 device 租约模式不再使用。调度循环约每 15 秒检查一次，并取得任务锁。
3. 执行前保存 `running` 状态；网络在工作线程执行。返回后重新读取最新任务集合，不能用请求前的整份快照覆盖暂停、删除、新增或改配置。
4. 结果写回保留用户最新配置、暂停/取消和新发出的手动运行请求；按最新配置计算后续时刻。已删除任务不复活。
5. 失败按 5 分钟起的指数退避重试，默认最多重试 3 次；超过预算暂停。`maxRetries=0` 现在确实表示不重试。
6. 轶闻领奖后的祈愿只入队，再走正常的锁、执行、记账、通知和退避路径，不绕过调度器另跑一次。
7. 通知由手机心跳拉取，发出成功才确认。KSU 同步失败也不会阻断独立的云通知拉取。

实现入口：`server/reamicro-api/app/api/tasks.py`、`scheduler.py`、`executors.py`。

## 3. 五类任务的状态机

| 任务 | 操作顺序 | 等待/重试 | 防重复和上限 |
| --- | --- | --- | --- |
| 每日轶闻 | 当天首次生成前按配置检查/祈禳 → `get-daily-lore` → 可领取才 `complete-daily-lore` | 优先用服务端 `endTime`；没有结束时间按小时查；暂未解锁或错误继续复查 | 保存日期、轶闻 ID、领奖完成日期；`isFinish` 表示可领奖，不表示已领奖 |
| 自动祈愿 | 等待同账号轶闻奖励已领取 → `wish` | 本地保存 `drawPending`；云端保存奖励触发标记，失败不消费该标记 | 默认每天 3 次，可配 1–20；0 表示用完可用彩筹；只发单次或九次请求，逐批累计成功次数 |
| 自动阅读 | 自选图书或最近阅读记录 → 逐本上报阅读时长 | 部分成功后失败保留已完成分钟和轮转位置 | 每本 1–720 分钟；默认每日总量 720 分钟；多本相加后限额，剩余额度不足时只上报剩余部分 |
| 自动行商 | 获取行商 → 在途等待 → `SETTLED` 后领取 → 按配置祈禳 → 续开 | 通常在真实 `endTime + 60 秒` 检查；已到时但结果未生成则短时复查；续开失败单独重试 | 通知、领取、续开分别按 tripId 记账；空配置沿用历史，允许合法的 `transportId=0` |
| 期物典当 | 查今日可典当期物与次数 → 查背包 → 逐次典当 | 每次成功保存进度，部分失败不是全部失败或全部成功 | 不超过官方剩余次数和持有量；跳过祈禳/传承/夺宝禁当物品；`success=false` 不计成功 |

日历口径为东八区。成功后的日常任务排到配置的下一个 `HH:mm`，不是简单加 24 小时；等待领奖和行商到达等阶段的指定时间优先。

「不祈禳」是明确的空配置；有相同签则沿用，不同签才替换。运签是账号的单一槽位，多个任务可能互相替换，不是每个任务各有一张独立生效的签。

## 4. 本轮修复和新增

- 本地领奖真正触发祈愿；即使在领奖落盘后、祈愿入队前退出，也能从状态重建待执行事件。
- 云端联动祈愿纳入正常重试；中途失败保留奖励触发标记，成功才清除。
- 阅读按实际多本累计分钟计账，支持每日上限小于单本配置时长，部分失败不丢已完成部分。
- 典当 API 放行原本已实现的 `pawn` 类型；失败响应不再当成功计数。
- Android/KSU 共用引擎；祈愿、阅读、轶闻和行商关键阶段、典当成功批次增加进度检查点。
- 网络返回后的状态不能重新启用刚关闭的任务，也不能覆盖最新配置；云端不能复活运行中被删除的任务。
- 网络执行转入 `JobService`，声明网络约束作业需要的 `ACCESS_NETWORK_STATE`；中断后不再继续发下一次接口请求；本地失败与云通知拉取隔离。
- root 命令并发处理输入/输出并限制等待时间，避免读输出时卡住而永远到不了超时判断。
- KSU 接管超时保持保守所有权，停用后才交回；请求队列、记录清空、重排和通知回执一起同步。
- 修复 Android `Files.getFileStore()` 直接抛 `SecurityException` 的运行时兼容问题，实机自检验证目录和状态文件的私有权限。
- 「配置 → 权限与后台」增加「隐藏后台卡片」；返回桌面/离开 Activity 后隐藏，重新进入时恢复，默认关闭，不执行强停或 `finishAndRemoveTask()`。

## 5. 仍有的边界与后续建议

### KSU 不等于永不掉线或绝对准点

- 设备关机不执行；深度休眠会暂停普通用户态计时。脚本没有编程硬件 RTC 闹钟，不能承诺熄屏状态每 15 秒准点醒来。
- 执行时尝试短时 wake lock，但是否可用取决于内核/SELinux；它不是全天持锁保活。
- 断网、登录失效、阅微接口限流/风控、root 权限被收回、模块被停用、守护进程被结束都可能造成延迟或失败。
- 任务执行和手机通知是两回事；模块仍可能因后台限制不能及时发通知。再次同步可读取已完成记录。
- 卸载前必须先切回 Android，保留最终进度。不要先删 APK/私有状态；未完成交接时不自动回退。
- KSU 运行时也不要清除模块应用数据：这会丢失应用里的执行权标记，而 root 守护可能仍在运行。重装/清数据前同样应先正常交接。

### 无法承诺接口「恰好一次」

上游请求已生效、但响应丢失或还没来得及写检查点就断电时，客户端无法精确知道这一次是否成功。轶闻/行商可再查服务端状态；祈愿等消耗型接口仍取决于官方幂等能力。云端的中途计数会在本轮结果写回时保存，服务器硬中断也有这个边界。不要把进度检查点解释为事务横跨手机和阅微服务器。

### 云端与本地没有跨设备分布式互斥

现有设置页在切换本地/云端时，会尽力停用另一端同类任务；这不是必须确认成功后的事务交接。断网、在模块独立页面修改配置或多台设备使用同账号，仍可能两端都启用。建议只保留一个执行来源；后续可增加「停用另一端确认成功后再启用」的显式交接流程。本轮严格交接覆盖的是 Android 本地与 KSU 本地，不是跨服务器互斥。

### 配置镜像发送方仍建议加固

历史 `LocalTaskMirrorReceiver` 是对外导出的兼容入口，目前未做发送方 UID 验证。普通应用有伪造镜像配置、干扰任务的风险；KSU 使用固定入口和固定接口，不允许借此传入任意 shell 命令，但不应把它当作解决了整个 IPC 的身份认证。正式推广前建议把配置写入迁到有调用方 UID 校验的 Provider/Binder，广播只负责唤醒，兼顾旧 Android 的兼容性。

### 服务端扩容要先改存储事务

本轮修复的是调度网络等待期间，旧快照覆盖新配置的竞态。当前状态存储仍有整命名空间读改写；这不代表可以安全地启动多个调度进程/多实例。多 worker、锁过期和长任务续租应单独审查，扩容前改成逐任务事务更新。

## 6. 验证范围

- Android 全量 JVM 单测，以及服务端全量单测；网络任务用测试 HTTP 服务/替身，不使用真实账号消耗道具。
- Release APK 构建及构建内的 lint vital 检查；所有 KSU shell 脚本语法检查和 ZIP 内容/权限检查。
- 连接设备以普通 shell（UID 2000）运行 APK 的 `KsuTaskMain self-test`，验证独立加载、共用引擎、原子状态读写、快照脱敏、目录 `0700` 和状态文件 `0600`；仅使用临时模拟数据，结束即清理。
- **尚未验证**：刷入 KSU 后真实 root 授权/接管、真实任务执行、重启恢复、长时间熄屏、网络切换，以及后台卡片按钮的设备点击表现。设备上未替换已安装 APK、未刷入模块、未切换现有任务模式。

运行命令：

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleRelease --console=plain
Push-Location server/reamicro-api
python -m unittest discover -s tests -p 'test_*.py'
Pop-Location
python tools/build-ksu-module.py
```

KSU 安装和回退步骤见 [KSU 使用说明](../ksu/README.md)。
