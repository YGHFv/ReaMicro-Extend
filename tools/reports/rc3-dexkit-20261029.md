## 起始根因

原 HostDexKit 主要校验已有 profile。RC3 初次运行时 B4 只有 8/360 匹配，
其余候选同样不匹配，正确拒绝旧映射后回退 identity，导致大量 ClassNotFound。
没有降低 90% 校验门槛，也没有直接把 B4 短名套到 RC3。

RC3 profile 保留 360 class、1047 method、1013 field，另有 181 typeAlias；
静态目标存在性检查 0 问题，运行期 DexKit 结构校验 360/360。
门面拆分以 methodOwner 表示；旧 B4 私有反射通过精确签名 ABI 表桥接，
业务逻辑和回调优先保持不变。

## 自动扫描

- 新增启动扫描、APK SHA-256 + 规则 SHA-256 + 引擎版本缓存、手动重扫与结果页。
- 入口：补全计划 → 关于补全 → DexKit 扫描。
- 434 条类/门面规则 + 866 条方法规则 = 1300 条；RC3 实机 1300/1300。
- 使用字符串、opcode、调用链、类型关系、返回/参数结构及必要数值消歧。
- DexKit 将 switch/array payload 表示为低字节 0，生成规则按相同视图保留位置。
- 多候选拒绝，不靠候选排序取第一项。扫描结果与已验证 RC3 映射逐项对比，0 漂移。
- 重扫不替换当前已装 Hook；结果与当前进程装载的扫描结果相同才提示无需重开。
- 旧 B2/B3/B4 的已验证 profile 不被 RC3 扫描规则反向污染。
- 未知构建可得到独立 automatic 部分符号表，但不会自动获得 RC3/B4 私有 ABI。

**边界：1300 项不是整个模块的全部反射依赖。** 仍有字段及部分接口/私有分支使用
版本 profile 和经过验证的 ABI，不能据此声称未来版本零适配，也不能将扫描全绿
等同于所有功能已经验收。完整业务参数变化仍需对照 REA/MT。

## 已确认差异与修复

- RC3 静态翻页和页边距编辑方法存在新增/收窄参数，profile 单独记录真实目标。
- MultiParagraphIntrinsics 从旧合并类拆出，不能继续与 HTTP RequestBuilder 共用身份。
- StringAnnotation 变为值类形式，保留真实构造器、字段及注解路径。
- 设置 LazyList、阅读搜索门面、导入、分页缓存和路由注册重新定位持有者。
- 个人页书院回调 `mb → nb`，仍是 byte=12；改用逻辑角色恢复发现入口，不改点击语义。
- 发现宫格 AspectRatio 移至 `qyb.b`，保持封面宽高比和列表/宫格布局。
- HTTP RequestBuilder 分支 13 → 12，URL/header/method 分别为 x/n/t。
- 单值 Flow 分支 5 → 6；RC3 的 5 是数组 Flow，隔离回归实际捕获并修复 ClassCastException。
- 保留 B4 对旧手动编辑扩展的禁用，不再在 RC3 加载已失效的外部 searchByThird/nav hook。
- 扫描合并保留既有 profile 的反向类身份，防止 typeAlias 变为主类造成类型判断回归。
